# MOSS Image AFM：2区間のブロック切り替え仕様

作成日：2026-10-28。会話で合意した機能と、その実装に必要な互換性方針を記録する。
対象：`AFM_for_MossImage_experimental`、調査時点の HEAD：`f47831f`。

## 合意した動作

- 単一の `MossImageAFM` ノードに2区間モードを追加する。
- OFFでは現在の1区間の動作を維持する。ONでは各区間に開始・終了・blockを指定できる。
- 両区間に該当する進捗では、第1区間だけを採用する。第2区間だけに属するblockも、その進捗では動作させない。
- どちらにも該当しない進捗ではAFMを適用しない。
- 周波数の計算、`strength`、CFG分岐、メモリ制限、エラー処理は共通設定とする。
- 周波数の倍率には生成全体の進捗を渡す。区間切り替え時に進捗を0へ戻さない。

| 設定例 | 開始 | 終了 | block |
|---|---:|---:|---|
| 第1区間 | 0.0 | 0.5 | `30-32` |
| 第2区間 | 0.5 | 1.0 | `0-2` |

この例では進捗 `0.5` を含めて第1区間、`0.5` を超えたら第2区間を採用する。
進捗は既存の `step_index / max(total_steps - 1, 1)` を使用する。
25ステップでは第1区間が13ステップ、第2区間が12ステップとなる。
途中開始・途中終了のサンプリングでも、現在と同様に実際に実行するスケジュール内の進捗を使う。

## 実装上の決定

以下は合意内容を具体化するための設計判断である。

| 入力名 | 既定値 | 用途 |
|---|---|---|
| `block_scope` / `start_percent` / `end_percent` | 従来の `0-2` / `0.0` / `1.0` | 第1区間。既存名・位置・既定値を維持 |
| `two_interval_mode` | `False` | 第2区間の有効化 |
| `second_block_scope` | `"0-2"` | 第2区間のblock |
| `second_start_percent` | `0.5` | 第2区間の開始 |
| `second_end_percent` | `1.0` | 第2区間の終了 |

- 両方のblock選択肢は `0-2`、`24-26`、`30-32`。内部テスト用の既存自由範囲パーサーは維持する。
- 新規4入力はスキーマ・実行引数・dataclassの末尾に追加し、入力省略時にも既定値で動くようにする。
- 新規入力はV3のoptional入力とする。既存のウィジェット順序を動かさない。
- 第2区間の入力欄はadvanced設定として常設し、OFFでは生成に使わない。動的な表示切り替えや独自JavaScriptは導入しない。
- ONにした際、既存の第1区間の値は自動変更しない。第1区間が `0–1` のままなら第2区間は全期間で優先負けするため、説明と例に明記する。
- 各区間は独立して `0 <= start <= end <= 1`。区間同士の時系列順序は強制せず、「第1」は設定の優先順位を意味する。
- 数値入力は常に型・有限性・範囲を検証する。第2blockの構文・モデル層数との照合は2区間モードON時だけ行う。
- ゼロ幅区間は、実際の進捗がその値に一致した場合だけ適用する。境界への丸めや許容誤差は加えない。
- 同じblockを両区間に指定しても、1つのAttention呼び出しにAFMを二重適用しない。

## 採用方式と対象外

採用方式は、単一ノード内で両区間のblockの和集合にフックを登録し、実行時に優先区間を選ぶ方式とする。
既存の単一RunStateとサンプラーwrapperを共有でき、会話で承認された操作と一致する。

直列ノード方式は現行の重複パッチ拒否と衝突し、今回の希望からも外れる。
サンプラーを前後に分ける方式は進捗やサンプラー状態の扱いを変えるため採用しない。

新規依存関係、3区間以上、区間ごとのstrength、周波数モード追加、任意block入力のUI公開、
ノード直列対応、他パッチとの互換性拡大、モデルの再学習は対象外。
Python 3.12以上、native ComfyUI MOSS、Euler / ER-SDEという現在の対象を維持する。

## 成功条件

境界・重複・空白区間・同一blockのテストで上記選択規則を確認する。
OFFと旧ワークフローの互換性、off/zero/observeの出力維持、全体進捗による周波数計算を確認する。
nativeテストとUI往復確認は実行環境と結果を明記し、未実行を成功扱いしない。
画質改善はこの機能の合否条件にしない。
